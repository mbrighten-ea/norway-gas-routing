4. RELEVANCE GATE FOR EVERY NEW DURABLE FILE

Apply these questions before creating or retaining a file. This is a normal
engineering check, not a permission request for every routine artifact.

A. Purpose: which user need, decision, calculation, regression or provenance
   requirement does it support? Give a concrete answer.
B. Consumer: which reader, report, command or test uses it? Important historical
   decisions and irreplaceable evidence also qualify without an active consumer.
C. Duplication: does an authoritative artifact already serve that purpose? Extend
   or replace that artifact instead of adding an overlapping copy.
D. Retention: must bytes be preserved, or can the file be deterministically
   regenerated from retained inputs/code? Regenerable intermediates are temporary
   by default; compact reader-facing results and key checks can still be retained.
E. Placement: route by purpose using the rules below, not by its creator's name.
F. Lifecycle: active, retained evidence, frozen milestone or temporary? State when
   replacement/retirement is appropriate. Do not delete by age automatically.
G. New category: can existing roles accommodate it? Material new top-level roles
   require agreement and an update to this plan before creation.

Outcomes: keep active; consolidate; retain evidence; archive; keep temporary; or
propose removal. A removal decision is not deletion approval.

Routing rules:
  Reusable calculation/application logic -> src/norway_gas_routing/
  Supported execution driver             -> scripts/run/
  Saved-artifact verification            -> scripts/verify/
  Repeatable input investigation         -> scripts/audit/
  Code behaviour/regression check        -> tests/unit/ or tests/integration/
  Shared synthetic test input            -> tests/fixtures/
  Authoritative reusable source input    -> data/raw/
  Reusable prepared input                -> data/processed/
  Durable input definition/investigation -> evidence/inputs/ or evidence/legacy/
  Main run explanation/results           -> outputs/<assessment>/ report/results
  Run-specific scores/flows/checks        -> outputs/<assessment>/details/
  Run-specific raw vintages/config       -> outputs/<assessment>/provenance/
  Frozen milestone/retired material      -> archive/
  Trial, test output, cache/intermediate -> .scratch/

Use one authoritative input/evidence copy. Link to its repository-relative path
and hash it from run provenance. A deliberately frozen reproduction snapshot is
the exception. Do not rewrite source bytes, silently overwrite archives or remove
evidence because the creating script has been retired.
